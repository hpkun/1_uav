# V2 空战环境设计审查

## 1. 审查范围与结论

本审查覆盖 `src/uav_combat/environment/`、3DOF 动力学和积分器、环境配置、MADSAC 训练接口、验证脚本、单元测试、V1.4 500k 诊断产物，以及 Li et al. (2023) 第 2.1、2.3-2.5、3.3.1-3.3.4 节。

结论不是继续调整 V1.4 阈值。V1.4 的工程稳定性已经足够，但其任务抽象把低层飞行响应、三条件硬门武器和弱势函数差同时交给策略探索。结果是一个稳定但大面积低信息的 Markov game。500k 策略能够接近，却没有足够的动作可控性和连续战术梯度把一次迎头交汇转换为尾追、射击窗口和击杀。

V2 应保留成熟的仿真骨架，重构动作到动力学之间的责任边界、射击规则、奖励分解和初始态分布。MADSAC 本身不是本次修改对象。

## 2. A. 当前 V1.4 设计

### 2.1 Dynamics

- 状态为 NED 坐标下的 `[x, y, z, v, theta, psi]`。
- 控制为切向过载 `nx`、法向过载 `nz` 和滚转角 `phi`。
- 使用论文一致的 3DOF 点质量方程和 `dt=0.1 s` 的 RK4 积分。
- 速度限制为 `[150, 300] m/s`，航迹俯仰限制为 `[-60, 60] deg`。
- 动力学和积分器已通过长期稳定性测试，不是 500k 失败的主要原因。

### 2.2 Action

- Actor 输出 3 维归一化动作。
- 实际语义是 `[切向加速度, trim-relative 法向过载增量, 滚转角]`。
- 映射为 `nx=2a0`、`nz=cos(theta)/cos(phi)+2a1`、`phi=60deg*a2`。
- 零动作可以定常平飞，解决了早期版本的垂直自毁问题，但策略仍直接操纵动力学输入。

### 2.3 Controller

- V1.4 没有独立的高层指令到飞机响应层。
- `control.py` 只是静态动作缩放和配平补偿，不追踪目标航向、目标俯仰或目标速度。
- 固定蓝方策略内部先计算期望方向，再反推归一化的 `nx/nz/phi` 动作。因此蓝方策略和 RL actor 都被迫理解低层控制量语义。

### 2.4 Observation

- 每个红方智能体使用 52 维局部观察。
- 自身 3 维：归一化速度、航迹俯仰、海拔。
- 3 个队友和 4 个敌机各占 7 维：自身航迹坐标系下的相对位置 3、相对速度 3、存活标志 1。
- 死亡槽位清零，自身死亡时整个观察清零。
- 不直接提供距离、攻击角、逃逸角或锁定状态。
- 表示具有水平平移和共同旋转不变性。

### 2.5 Reward

- 事件奖励：击杀 `+10`，死亡 `-10`；同一目标由多个攻击者击杀时均分击杀奖励。
- 稠密奖励是战术势函数差：`r_shape = Phi(s') - Phi(s)`。
- 单对得分为距离、攻击角和逃逸角三个 `[0,1]` 得分的乘积。
- 个体势函数是最强攻击得分减最强受威胁得分。
- 无能量、编队、水平边界或中心返回奖励。

### 2.6 Weapon

- 硬射击条件为：距离不大于 `1500 m`、攻击角不大于 `45 deg`、逃逸角不大于 `90 deg`。
- 三个条件必须同时成立。
- 同一目标连续满足 3 个仿真步后确定性击杀。
- 每步自动选取当前可攻击目标，双方同时结算，因此允许同一步互毁。

### 2.7 Initialization

- 双方中心固定相距 `6000 m`，以随机直径方向旋转整个场景。
- 双方均为间距固定的 line-abreast 队形，几乎正迎头飞行。
- 仅速度、海拔和航向有小扰动。
- 随机性改变全局朝向，但不改变相对空战类型，绝大多数 episode 仍是同一种迎头交汇。

### 2.8 Boundary

- 当前没有水平软边界、恢复区或中心返回控制。
- 只有海拔 `[500, 8000] m`，越界飞机判定死亡。
- 水平坐标不参与奖励或终止。

### 2.9 Blue policy

- 每步选择最近存活红机。
- 使用 pure pursuit 指向目标，并维持固定目标速度。
- 策略简单、确定、可复现，但其动作生成仍依赖 V1.4 的低层动作语义。

## 3. B. 当前设计与空战 RL 任务的偏差

### 3.1 为什么 500k 没有形成 combat chain

完整 combat chain 应为：发现并接近目标 -> 交汇前选择几何 -> 交汇后持续机动 -> 获得射击窗口 -> 保持窗口 -> 击杀或规避威胁。

500k 诊断显示：最终策略到达 `4 km` 和 `1.5 km` 的比例均为 1，但红方硬射击条件占比为 0；平均滚转角绝对值只有约 `0.0069 rad`。它学会了稳定接近，却几乎没有执行足以改变交汇几何的转弯。原因是以下模块共同形成的，不应归咎于单一超参数。

### 3.2 Reward 导致的偏差

1. 初始攻防对称使 `max attack - max threat` 接近 0。迎头接近时双方得分同步变化，差值继续接近 0。
2. 单对得分是距离、攻击角、逃逸角的乘积。任一项接近 0 时，另外两项的改进几乎不可见，形成大面积平坦区。
3. 势函数差只奖励一步状态变化。持续保持有利态势没有正反馈；短时改善之后只要势函数不再增加，奖励立即回到 0。
4. 多目标使用 `max`，目标切换会造成不连续，并掩盖次优但正在改善的交战关系。
5. 远距离接近、角度优势、进入射击窗口和完成驻留没有可分辨的奖励通道。critic 很难判断失败发生在 chain 的哪一段。
6. V1.4 验证中 straight baseline 的 shaping 中位数为 0；rule baseline 也有大量零值和约 `1e-4` 量级的小反馈，相比熵项与 `+/-10` 事件过弱。

### 3.3 Action abstraction 导致的偏差

1. Actor 必须同时学会配平、转弯过载、俯仰变化和速度变化之间的耦合，才能表达一个简单的“向左转并保持高度”。
2. `phi` 是姿态控制量而不是战术意图。一个固定 `phi` 动作代表持续转弯，策略还必须学会何时回正。
3. `nz` 同时决定俯仰率并通过滚转参与航向率。策略需要发现动力学解析关系，才可能稳定地实现三维追踪。
4. 固定蓝方先计算战术目标，再反推低层动作；RL actor 没有同样的高层响应层，比较并不对称。
5. 稳定直飞是容易发现、低方差且不触发海拔损失的策略，因此在弱 reward 下成为吸引子。

### 3.4 Attack model 导致的偏差

1. 距离、攻击角、逃逸角是硬交集，窗口体积小；三步连续驻留又进一步缩小有效事件概率。
2. 逃逸角以单一阈值参与硬门。迎头时攻击角很好但目标态势最差，交汇后目标态势可能改善而攻击角迅速恶化，两者几乎没有重叠。
3. reward 使用与武器相同几何的乘积版本，不能为“先改善最差条件”提供稳定梯度。
4. `1.5 km` 最大距离使高速 4v4 交汇中的有效时间很短。以约 `450 m/s` 闭合速度计算，窗口前后变化以秒计。
5. 自动选择可攻击目标加 `max` reward 选择使 target relation 不稳定，连续锁定容易因目标切换或一步越界而清零。

### 3.5 Initial state 导致的偏差

1. 随机全局旋转不等于随机战术态势。相对几何始终接近对称迎头。
2. 所有训练样本先经历相同的直线闭合，再经历高难度交汇。策略很少看到 offset、crossing 或 flank 状态下“正确机动能直接改善态势”的样本。
3. 初态同时让攻击角容易、目标态势角极差，恰好暴露武器硬交集和乘积 reward 的最弱区域。
4. 这不是任务太难，而是状态分布单一且梯度方向冲突。增加轻微噪声不能解决。

### 3.6 Observation 导致的偏差

1. 原始相对位置和速度足以推导距离、LOS、闭合率和目标态势，因此缺失派生角不是主要问题。
2. 观察没有显式锁定状态是合理的，因为锁定是武器内部结果，不应成为策略捷径。
3. 问题在于相对值没有限幅，远距离 episode 后可能远超标称归一化范围，降低网络数值一致性。
4. 固定 ID 槽位允许协同，但 reward 和武器选择按瞬时最佳/可攻击目标切换，观察槽与奖励目标之间没有稳定对应。
5. 不应通过直接加入距离、攻击角、锁定状态解决上述契约问题。那会把环境内部判据泄漏给 actor，而没有修复任务结构。

## 4. C. 模块处置决策

### 4.1 保留不变

- 3DOF NED 点质量动力学方程。
- RK4 积分和 `0.1 s` 仿真步长。
- 4v4 同构红方智能体和固定蓝方框架。
- MADSAC actor、双 attention critic、replay、更新调度和评估种子协议。
- 3 维连续动作接口和 52 维观察维数，避免无研究价值的网络改动。
- 观察的自身航迹坐标系表达、固定队友/敌人槽位和 alive mask。
- 仅海拔作为必要物理空间限制。
- 双方同一步射击事件的同时结算。

### 4.2 修改

- `control.py`：从直接过载映射改为高层 maneuver command 到 3DOF 控制的简单响应层。
- `fixed_policy.py`：直接生成高层期望航向、俯仰和速度，不再反推过载动作。
- `weapon.py`：改为距离、离轴角、目标态势角的明确 firing window 和短驻留。
- `reward.py`：改为 engagement progress、tactical advantage、fire opportunity、combat event 四通道。
- `scenario.py`：统一采样 head-on、offset、flank 三类真实开始态势。
- `observation.py`：保持信息集合和维数，增加归一化限幅并明确 feature 契约。
- `env.py`：重组 reward 时序、目标关系、窗口/锁定统计和 V2 info。
- 配置、验证脚本、测试和文档同步到 V2 语义。

### 4.3 删除

- 旧的 `[nx, trim-relative nz, phi]` actor 动作映射。
- `trim_normal_load` 作为 actor action 语义的公开核心逻辑。
- `engagement_score` 三项乘积及 `tactical_potentials` 势函数差奖励。
- V1.4 的 reward 配置字段 `shaping_lambda` 和 `engagement_distance_scale`。
- 只验证 V1.4 冻结语义的诊断耦合与旧 validation gate。
- 文档中将 active environment 描述为 V1.4 的内容。

不引入 PID、航迹规划、导弹动力学、能量管理奖励、编队奖励、水平返回区、课程学习、通信或异构角色。

## 5. 论文一致性边界

Li et al. (2023) 明确使用 3DOF 点质量模型，并让 actor 输出 `[Delta psi, Delta theta, Delta v]`，再由未公开的 controller 转换到动力学控制。论文的攻击规则也是自动射击的距离和角度窗口，固定蓝方为最近目标追踪。V2 采用相同的“高层决策层 + 简单飞机响应层 + 自动射击规则”研究抽象。

V2 不声称复现论文未公开的 controller 增益、武器概率参数或初始化细节。它追求 paper-consistent，而不是 paper-identical：保留论文研究问题的层级分工，同时用公开、确定、可测试的参数构造可学习环境。
