一、修正 ValueNormalizer 与 Critic 输出空间不一致

当前实现存在明确问题：

1. Critic 网络输出被当作 normalized value；
2. Runner 使用当前 ValueNormalizer 将其 denormalize 后存入 rollout；
3. Trainer 收到 rollout 后先更新 ValueNormalizer；
4. old value 和 return 使用更新后的统计量重新 normalize；
5. 当前 Critic 输出却仍处于更新前网络所对应的坐标语义；
6. 因而在第一次 PPO 更新、参数尚未变化时，new value 与 old value 已可能不一致；
7. value clipping 可能因此错误触发。

本轮采用简单、清楚且可审计的修正，不实现 PopArt。

统一定义：

- Critic 网络始终输出物理奖励尺度下的 value；
- rollout buffer 中的 value 始终是物理尺度；
- GAE 和 return 始终是物理尺度；
- ValueNormalizer 只用于计算 Critic loss 时统一归一化：
  - new physical value
  - old physical value
  - physical return target
- 三者必须使用同一时刻、同一组 mean/variance；
- Actor、GAE 和环境奖励不经过 ValueNormalizer。

具体修改：

1. `MAPPORunner._values()`：
   - 直接返回 Critic 输出；
   - 删除 ValueNormalizer.denormalize。

2. rollout 收集：
   - Critic 输出直接作为 physical value 保存；
   - 删除 collect 中的 denormalize。

3. `MAPPOTrainer.update()`：
   - 原始 `old_values`、`returns` 都是 physical scale；
   - 更新 ValueNormalizer 后，使用同一个 normalizer 分别得到：
     - normalized_returns
     - normalized_old_values
     - normalized_new_values
   - `ppo_value_loss()` 的 new、old、target 必须全部处于 normalized scale；
   - 当 `use_value_normalization=false` 时，三者全部保持 physical scale。

4. explained variance：
   - Critic 输出已经是 physical value；
   - 直接与 physical returns 比较；
   - 不再调用 denormalize。

5. 文档明确：
   - Critic 输出 physical value；
   - ValueNormalizer 是 value-loss target normalization；
   - 不是 PopArt；
   - 不会改变 Critic 输出层的数值语义。

6. 检查整个项目，删除所有把 Critic 输出默认解释为 normalized value 的代码和文档。

二、处理旧 checkpoint 兼容问题

由于 Critic 输出语义发生变化：

- checkpoint 版本提升到 v3；
- v2 checkpoint 允许 `actor_only=True` 加载；
- v2 checkpoint 不允许 full resume；
- full resume 时给出明确提示：
  “v2 critic value semantics are incompatible with v3 physical-value critic”；
- v3 checkpoint 正常保存和恢复：
  - Actor
  - Critic
  - optimizer
  - ValueNormalizer
  - minibatch RNG
  - environment state。

不要编写复杂迁移器，也不要尝试猜测并转换旧 Critic。

三、增加 ValueNormalizer 核心测试

新增或修改测试，必须验证：

1. `use_value_normalization=false`：
   - Critic new、old、target 全部使用 physical scale。

2. `use_value_normalization=true`：
   - new、old、target 使用同一 normalizer；
   - 在 Critic 参数未更新时：
     new physical value == old physical value；
   - 归一化后：
     normalized new value == normalized old value。

3. 更新 normalizer 均值和方差后：
   - 未更新网络的 new/old value 差仍为0；
   - value clipping 不会仅因 normalizer 变化而触发。

4. GAE 使用 physical value。

5. explained variance 使用 physical prediction 和 physical return。

6. v2 full resume 被拒绝；
7. v2 actor-only 可以加载；
8. v3 full resume 后下一次 rollout 和更新一致。

五、拆分真正的空战胜利与超时存活胜利

当前 timeout 时根据存活数量判断 winner，这是环境规则，可以保留。

但评估指标必须拆分：

- overall_red_win_rate
- elimination_win_rate
- timeout_survival_win_rate
- decisive_win_rate
- draw_rate
- timeout_rate

定义：

`elimination_win_rate`：

- 蓝方全部失效；
- termination reason 为 blue_eliminated。

`timeout_survival_win_rate`：

- termination reason 为 timeout；
- 红方因存活数量更多被判胜。

`decisive_win_rate`：

- 红方获胜且不是 timeout。

`overall_red_win_rate`：

- 保留当前所有红胜。

正式报告不能把：

“100% timeout 且红方存活数量更多”

描述成完成了空战制胜。

七、分离 validation 和 final test seeds

训练过程中：

- 最终 summary 只把 test 结果作为正式结果；

八、修正跨训练 seed 的置信区间

规则回合中的二项比例继续使用 Wilson interval。

跨训练 seed 的均值，例如3个或5个独立训练 seed，使用 Student t interval：

mean ± t_(n-1,0.975) * sample_std / sqrt(n)

可以直接使用 scipy.stats.t.ppf。

输出中明确字段：

- confidence_interval_method: student_t
- num_training_seeds

不要将跨训练 seed 的区间裁剪到 [0,1]；原始统计区间保留，展示胜率时可额外提供 clipped display interval，但不能替换原值。
